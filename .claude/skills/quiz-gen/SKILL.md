# クイズ問題生成スキル

ranges.ts のレンジデータに基づいてクイズ問題を生成し、quiz-data.ts に追加する。

## ワークフロー

### ステップ 1: 現状分析

既存データを読み込み、カバレッジを確認する。

1. `src/data/quiz-data.ts` を読み、既存の問題一覧を把握
2. `src/data/ranges.ts` を読み、全シナリオとレンジを把握
3. 以下のカバレッジ表を作成してユーザーに提示:

```
| シナリオ     | 既存問題数 | 使用済みハンド        |
|-------------|-----------|---------------------|
| ep-open     | 0         | -                   |
| ep-vs-tight | 0         | -                   |
| ...         | ...       | ...                 |
```

### ステップ 2: 生成計画

ユーザーと生成内容を合意する:

- **対象シナリオ**: 未カバーのシナリオを優先
- **問題数**: シナリオあたり 3〜4問を目安
- **ハンドカテゴリの分布**: 明確Raise / 明確Fold / ボーダーライン / スーテッド差

ユーザーの確認を待つ。

### ステップ 3: 問題生成（エージェント呼び出し）

`quiz-question-generator` エージェントをシナリオ単位で呼び出す。

**呼び出し方法**: Agent ツールで以下を指定:

```
Agent({
  subagent_type: "quiz-question-generator",
  description: "Generate quiz questions for {scenario}",
  prompt: "以下の条件でクイズ問題を生成してください:
    - 対象シナリオ: {scenario_id}
    - 生成数: {count}問
    - 避けるべきハンド: {existing_hands}
    - 開始ID: {next_id}
  "
})
```

**並列実行**: 独立したシナリオは並列でエージェントを起動できる。
ただし、一度に起動するエージェントは最大3つまでにする。

### ステップ 4: レビューと調整

エージェントの出力をレビューする:

**チェック項目**:

1. **正解の正確性**: レンジデータと照合して正解アクションが正しいか
   - ハンドが reraise レンジにある → リレイズ/3-Bet/4-Bet が正解
   - ハンドが flat レンジにある → コール が正解
   - ハンドが raise レンジにある → レイズ が正解
   - どのレンジにもない → フォールド が正解

2. **解説の質**: ポーカー戦略として正確で教育的か

3. **バランス**:
   - 正解アクションの分布（Raise/Fold/Call が偏りすぎていないか）
   - ハンドタイプの分布（ペア/スーテッド/オフスートが混在しているか）

4. **重複チェック**: 同じハンド × 同じシナリオの問題がないか

問題があれば修正する。ユーザーに最終確認を求める。

### ステップ 5: quiz-data.ts への反映

レビュー済みの問題を `src/data/quiz-data.ts` に追加する。

**手順**:
1. 既存の `quizQuestions` 配列の末尾に新しい問題を追加
2. ID が連番になっていることを確認
3. TypeScript の型エラーがないことを確認（`npm run lint`）

### ステップ 6: 20問ランダム出題の実装確認

問題が20問を超えた場合、出題ロジックの変更が必要:

- `src/app/quiz/page.tsx` でシャッフル後に `.slice(0, 20)` を追加
- 総問題数と出題数を UI に表示（例: 「全45問から20問を出題」）

この変更が未実装なら、ユーザーに実装を提案する。

## エージェントのカスタム利用

スキルは `.claude/agents/quiz-question-generator.md` のエージェント定義を使用する。
エージェントは以下を読み取って問題を生成する:

- `src/data/ranges.ts`: 正解判定の根拠
- `src/data/quiz-data.ts`: 既存問題（重複回避）

## 注意事項

- すべての UI テキスト・解説は**日本語**で記述する
- レンジデータに存在しないハンドを「レンジ内」として出題しない
- `ranges` が空のシナリオ（`btn-vs-tight`, `co-vs-tight`）では `notes` を参考にして問題を作る
  - これらのシナリオでは基本的にフォールドが正解
- 1シナリオ内でも状況文（situation）にバリエーションをつける
